# 生产环境踩坑与用户偏好手册

> 本文档来自真实项目《团圆饭》（12 幕白板动画 + TTS 朗读 + BGM），
> 记录了从出图到成片全链路的失败案例、根因与正确做法。
> **先读本文，再动手**，能避开本文列出的所有坑。

---

## 一、用户偏好倾向（重要，先理解再动手）

| 倾向 | 具体表现 | 应对方式 |
|---|---|---|
| **零容忍演示模式** | 要求真实可用实现，不接受占位/假数据 | 任何"先跑个假的看看"都会被否决 |
| **先查日志再改码** | 反对盲目改代码 | 诊断清楚再动手，把根因说清楚 |
| **验证前先重启服务** | 改完服务端要重启才生效 | 改配置后确认服务已重载 |
| **主动质疑 AI 结论** | 会追问"你是不是没按XX 做" | 他指出的问题多半是真的，认真核对 |
| **细节洁癖** | 会数出"第 5 幕和第 6 幕重叠了 0.5 秒"这类问题 | 交付前必须跑量化校验，不能靠肉眼 |
| **要求一致的风格** | 一次不满意就全量重做（12 张） | 风格基准要一次定死，写进 PROMPT-BASE 复用 |
| **修改局部不动全局** | 只重做指定的那一幕 | 渲染脚本要支持单幕参数覆盖 |
| **AI 回复要具体** | 讨厌"已优化""已修复"这类空话 | 报告必须带数字：多少秒、多少 dB、改了哪个文件 |

**沟通要点**：用户提问里如果陈述了具体现象（如"中间有一段有重叠"），
那是他**已经验证过的事实**，直接查数据确认，不要质疑。

## 二、出图阶段

### 2.1 提示词里写"禁止彩色"，模型照样画彩色

- **现象**：即使写了 `NO colour of any kind`，模型仍会画彩色描边、彩色地面光晕、人物皮肤色。
- **正解**：提示词约束 + **后处理双色调**双管齐下。
- **不要用简单去色**：`desaturate.py` 用饱和度阈值直接去色，会把**暖米黄纸底一起灰化**
  （实测 99% 像素被处理），破坏 skill 要求的纸色。
- **正解做法（duotone.py）**：只用**亮度**做映射，暗端墨色 → 亮端纸色：
  ```
  INK   = #3C3A38   （替代纯黑，避免死黑）
  PAPER = #F5EBD7
  t = clip((lum - black) / (white - black), 0, 1) ** gamma
  out = INK + (PAPER - INK) * t
  ```
  所有像素只依赖亮度 → 任何残留的橙/蓝/红都会被拉回这条暖色轴，12 张色调自动统一。

### 2.2 建筑容易画成城堡

- **现象**：老厂房/老院子被画成带瓦片尖顶、塔楼、城垛的城堡。
- **正解**：提示词里正向描述要具体（平顶、钢框多格窗、砖烟囱+通风筒+圆柱水塔），
  同时**显式列禁用项**：瓦顶 / 尖顶 / 城垛 / 塔楼 / 城堡门 / 童话小屋 / 中世纪石工。

### 2.3 出图右下角有 "AI生成" 水印

- **正解**：`clean_watermark.py` —— 取角落邻域**众数色**当纸色，回填右下角矩形块。
- **要点**：只回填 `alpha>20` 的角落（该角落本就是空白纸面），
  留 18px 边缘羽化带避免出现可见直边。
- 注意 `assets/drawing-hand.png` 的 alpha 有效区已裁剪，水印在区外不会带入。

### 2.4 人物年龄/设定在 12 张图里漂移

- **正解**：把角色设定写成**逐字复用的固定段落**（`PROMPT-BASE.md` 的 ROLES 段），
  每张图的提示词都原样粘贴这段，只替换 SCENE 段。仅靠"保持一致"这种描述无效。

## 三、标注阶段

### 3.1 自动分块对细密线稿无效

- **现象**：形态学连通域把整幅画合成一块（墙面/窗格/砖缝彼此相连），
  dilation 从 9 调到 1 都无效。
- **正解**：`grid_overlay.py` 叠加 0.05 步长的归一化坐标网格，人眼读出主体网格位置，
  写进相对比例，脚本换算像素。**目测坐标偏差极大**（实测人物框偏高 20%+）。

### 3.2 时序分配会超出幕时长

- **症状**：渲染日志报"末元素结束 XXXX 超出幕时长 YYYY"。
- **根因**：呼吸间隔按固定 500ms 累加，元素多时必然溢出。
- **正解**：`lead + n 段作画 + (n-1)×gap + tail = 幕时长`，
  并让**最后一个元素吃掉所有余量**。

## 四、渲染阶段

### 4.1 铅笔手不见 / 只露笔尖

- **根因**：`TipOverlay` 的 `tip_anchor` 缺省值是 `(0,0)`，即把**素材左上角**对准落墨点，
  整只手被推出画布外。
- **正解**：量出笔尖在素材有效区的真实位置。方法：
  1. 按颜色阈值取笔杆掩膜（笔杆是暗红棕，`R-G≈30~55`）
  2. PCA 求主轴，两端即笔尾/笔尖
  3. 笔尖归一化坐标即为 `tip-anchor-x/y`
- 内置 `drawing-hand.png` 实测：**`(0.21, 0.68)`**（有效区 542×668）。
- **镜面翻转**后 x 变成 `1 - x` → `(0.79, 0.68)`。翻转可让笔尖朝向符合右手书写方向。

### 4.2 手部素材与线稿风格不匹配

- **现象**：内置手部是**写实 3D 手**，贴在扁平线稿上非常突兀。
- **正解**：把手的像素也过一遍 duotone（保留原 alpha 通道），生成风格一致的手部素材。

### 4.3 手太大盖住画面

- **现象**：`target_hand_height` 硬编码 493（按 1080p 调校），小画面下占近半屏。
- **正解**：新增 `--hand-height` 参数（本 skill 已加），线稿细腻时用 240–320。
- 尺度过大时手会遮挡正在画的内容，抽帧检查笔尖是否仍贴合笔迹。

## 五、TTS 阶段（豆包语音合成 2.0）

### 5.1 鉴权：两套体系，别混用

| 体系 | 需要的东西 |
|---|---|
| **新版（推荐）** | 1 个 `X-Api-Key` 长字符串 + `X-Api-Resource-Id` |
| 旧版| `APPID`（纯数字）+ `Token`（JWT）+ Cluster |

**新版三个关键点**（缺一个都不行）：

1. **资源 ID 是 `seed-tts-2.0`（连字符），不是 `volc.seedtts.v2`（点号）**。
   点号那种是旧版 `volcengine_tts` 服务的命名，用错会一直报
   `403 resource not granted`，容易被误判成"模型没开通"。
2. **body 必须用 `req_params` 结构**，且 `user.namespace = "BidirectionalTTS"`，
   否则报 `55000000 resource ID is mismatched with speaker related resource`。
3. **响应是 chunked 多行 JSON**：每行 `code=0` 且 `data` 是 base64 音频片段；
   末行 `code=20000000 data=null` 表示结束。**不是单个 JSON 响应**。

### 5.2 用对照实验判断"key 坏了"还是"资源没授权"

这是最容易判断错的地方，务必用这个方法：

| 实验 | 结果 | 结论 |
|---|---|---|
| 随便编一个 key | HTTP **401** `Invalid X-Api-Key` | key 无效 |
| 用户给的 key | HTTP **403** `resource not granted` | **key 有效，只是资源没授权** |

**403 反而是 key 有效的证据。** 不要因为看到 403 就断定"key 格式不对"——
有些 API Key 恰好长得像 UUID（形如 `xxxxxxxx-xxxx-xxxx-...`），不能凭形状判断。

### 5.3 WebSocket 版需要特定子协议

若必须用 `wss://.../api/v3/tts/bidirection`，服务端会返回
`{"error": "decode ws request failed: unsupported protocol version 7"}`。
这是**WebSocket 子协议版本协商**问题，不是鉴权问题。
**能用 HTTP 版就别用 WebSocket 版**，省掉协议实现的全部复杂度。

### 5.4 TTS 语速普遍快于目标，需 atempo 校正

- **现象**：豆包 TTS 实测 **4.6~6.5 字/秒**，散文朗读目标通常 3.5~4.25 字/秒。
- **正解**：`atempo` 只改时长不改音高，按每句**实测**语速校正：
  ```
  actual_rate = chars / 实测时长
  tempo = 目标语速 / actual_rate       # atempo>1 加快，<1 放慢
  ```
- **首次容易写反**：`atempo > 1` 是**加快**。语速过快需要**放慢**，tempo 必须 **< 1**。
  写反会让语速飙到 8~10 字/秒。
- 限幅 `clamp(0.5, 2.0)`，超出范围音质会明显受损。

## 六、混音阶段（三个连环坑）

### 6.1 逐句"补静音再拼接"会让长度爆炸

- **症状**：`voiceover.wav` 长度 **917.95s**（应为 83.45s），从第 2 句起全部错位。
- **根因**：每句都 `-t totalSec`（补静音到全片末尾），11 句 concat → 11 × 85 = 917s。
- **第一次修错了**：改成 `-t 本句结束`，仍不对（变成 507s）。
- **正解**：用 `filter_complex` **一次性叠加**，每句只经 `adelay` 偏移：
  ```
  [0:a]atempo=X,adelay=ms|ms[v0] ... [n:a]...[vn]
  [v0][v1]...[vn]amix=inputs=N:duration=longest:normalize=0[mix]
  [mix]apad,atrim=0:TOTAL[out]
  ```
  输出长度由最后的 `atrim` 决定，不会累加。

### 6.2 `apad` + `duration=longest` 会摊薄其他音轨

- **症状**：BGM 片尾掉到 **−76dB**，几乎听不见。
- **根因**：`apad` 把旁白变成"无限长"，`amix` 按最长输入分配权重，
  BGM 那一路被摊薄到接近 0。
- **正解**：不要对混音输入用 `apad`；若必须，先 `atrim` 到目标长度再叠加。

### 6.3 `duration=first` 会截断较长的音轨

- **症状**：音轨 83.45s，视频 89.78s → 片尾 6.4 秒 BGM 整段消失。
- **根因**：`duration=first` 以**最短输入**为准。
- **正解**：先给**每一路**都 `apad + atrim=目标长度`，此时各路等长，`first` 无副作用。

### 6.4 最隐蔽的坑：BGM 自身的 afade 淡出

- **症状**：混音怎么调，片尾都是 −60dB 以下。
- **根因**：BGM 生成时加了 `afade=t=out`，**淡出把末尾几秒削成了静音**。
  混音层无论怎么修都救不回来。
- **正解**：
  - 若需要片尾淡出，淡出区必须**短于**片长（例如片长 89.8s，淡出 84→87s）
  - 更稳妥：**BGM 不做淡出**，或改在混音后用 `afade` 且 `st` 取 `片长 - 淡出时长`
  - 循环用 Python `np.tile` 平铺，**不要用 ffmpeg `-stream_loop`**（它会在末尾截断）
  - **循环次数**：`ceil(目标时长 / 源时长)`

### 6.5 最稳妥的混音实现

**放弃 ffmpeg 滤镜混音**（自动增益逻辑难预测），改用 numpy 逐样本相加：

```python
a = read_wav(voice) * VOICE_GAIN        # 旁白增益
b = read_wav(bgm)  * 10**(BGM_DB/20)   # BGM 电平
mix = a + b
peak = np.abs(mix).max()
if peak > 0.99:
    mix = np.tanh(mix * 1.05) * 0.95    # 软限幅，不用硬 clip（会产生失真）
```

再用 `loudnorm=I=-16:TP=-1.5:LRA=11` 标准化整体响度。

### 6.6 测电平必须用 ffmpeg volumedetect

- **陷阱**：用 PyAV 手工解码多声道算 RMS，**会得到错误数值**，
  曾据此误判"BGM 正常"（实际已静音）。
- **正解**：`ffmpeg -ss X -t Y -i F -af volumedetect -f null -` 逐段测。

## 七、成片校验（交付前必做）

### 7.1 遮罩不变量：量化而非肉眼

导出每幕**结尾帧**与源图比"墨迹覆盖率"：
```
ratio = (结尾帧暗像素占比) / (源图暗像素占比)
```
12 幕全部 ≈ 1.00 才算通过。肉眼容易把"绘制中的中段帧"误判为元素丢失。

### 7.2 声画对齐：必须做程序化校验

**这是最容易出错、最容易被用户抓到的地方。** 逐条检查：

| 检查项 | 判据 |
|---|---|
| 幕号完整 | 语音单元数 == 画面幕数，**一一对应** |
| 无重叠 | `units[i].start >= units[i-1].end` |
| 不越幕 | 每句 `[start, end]` 完全落在本幕窗口内 |
| 起点一致 | 各句相对本幕起点的偏移量应基本相同 |

**致命教训**：曾经 12 幕里**漏了第 5 幕**的语音单元，
导致该句被当成单幕处理，**后 7 句全部累积偏移 −5.93 秒**，
表现为"越到后面字幕越快于画面"。用户描述为"你是不是没按照幕数去对齐"。

**防御措施**（必须实装）：
1. 在对齐脚本里**主动检查缺失**并报错，而不是静默跳过：
   ```python
   missing = [s for s in scene_order if s not in units]
   if missing: raise SystemExit(f"这些幕没有语音单元：{missing}")
   ```
2. 对齐后再跑一遍校验，**不通过就 exit(1)**，不要产出成片。

### 7.3 语音不该撑满整段

用户明确要求"按正常语速读完，画没画完就放背景音乐"。

做法：`duration = 字数 / 目标语速`，句末留白 `rest = 幕可用时长 - duration`。
留白期间由 BGM 填充，不冷场。
对齐脚本应输出 `restSec` 字段方便检查。

### 7.4 字幕与原文一字不差

- **朗读文本 ≠ 字幕文本**：朗读为了换气会加逗号、破折号；
  字幕必须用**用户输入的原文**，一字不增删。
  → 维护两份：TTS 用 `speak`，字幕用 `subtitle`。
- **合并字幕时**：一句字幕覆盖多幕，字幕也要拆成多条分别落在各自画面时段。
- **交付前逐字校验**：`concat(字幕) == concat(原文)`，按字符比对。
- **长句折行**：按像素宽度逐字断行，**不增删任何字符**。
- **ffmpeg 缺字幕滤镜时**：homebrew 的 ffmpeg 可能未编译
  `--enable-libass` / `--enable-libfreetype`，`ass` 和 `drawtext` 都不可用。
  改用 PIL 逐帧渲染字幕，再让 ffmpeg 只做封装（`-c:v copy`）。

## 八、TTS 缓存陷阱

`audio_build.py tts` 用 `NN.mp3` 做文件名并跳过已存在文件。
**一旦句子顺序或内容变了，编号会与内容错位**，且不会报错——
表现为"某些句语速异常"（因为拿到的音频内容不对）。

**防御**：
- 改句子后**清空缓存目录**再重跑
- 或用 `内容哈希` 作文件名（更稳妥，推荐）
- 或在 `assemble` 里校验每句字数与音频时长是否匹配（见 7.2）

## 十一、流水线化改造（从"手工拼命令"到"给文字出成品"）

实战验证后发现：配音相关脚本若按项目硬编码，换个项目就全废。
应改造成**配置驱动**的流水线。

### 架构

```
scripts/make_project.py   文字 → config.json + original.txt + 目录
        ↓
   （出图 + 标注）
        ↓
   render_*/merge_scenes   画面
        ↓
scripts/build_audio.py    plan → tts → assemble → mix → 校验 → 成品
```

### 关键设计

| 设计 | 理由 |
|---|---|
| **一切参数进 config.json** | 语速/BGM/配色/音色都不写死在代码里 |
| **`text` 与 `speak` 分开** | 字幕用原文；TTS 可加换气标点。混用会导致字幕多字 |
| **TTS 缓存用内容哈希** | 用序号命名会在改句子后编号错位且不报错 |
| **先build_timeline 再合成** | 时间轴错位能在合成前发现，省 TTS 调用 |
| **mix 返回带音轨路径给字幕步** | 否则字幕步会从无声画面取音轨，输出丢音频 |
| **verify 校验最终成品** | 校验无声画面源会误报"疑似静音" |

### 测试时发现的真实 bug（值得记住）

跑通端到端测试（3 幕假标注 + 真实线稿 + 真实 TTS）时暴露：

1. **标注查找只在 config 有 `image` 字段时才走 fallback glob**
   → config 不带 image 时直接报"找不到标注"。**fallback 路径必须无条件执行。**
2. **mix 产出 `{name}-final.mp4`，后续步骤若用"自动选画面"会选到自己**
   → 选画面时必须排除 `-final.mp4` / `-final-subtitled.mp4`。
3. **原画面完全无声**，`-map 1:a` 报 "matches no streams"
   → 先 `_has_audio()` 探测，无声则 `-an`。
4. **字幕步用了无声画面做音轨源**，成品丢音频
   → 显式传 `audio_src=mixed`。
5. **verify 测的是无声源**，报 2 段"疑似静音"，但成品实际正常
   → verify 必须指向最终成品。

> 教训：**任何"自动选择文件"的逻辑都要防自引用**；
> 多步流水线每一步的输入输出路径要显式传递，不要依赖glob 猜测。
